# MAP-006 — Add platform-only camera observation adapter for MapLibre

## Context
Current map rendering is already separated from feature state, and Android-specific MapLibre integration stays in `androidMain`.

The next step is to read camera values from MapLibre Native without leaking MapLibre-specific APIs into shared code and without coupling camera observation to business logic.

We need the smallest possible adapter seam that reads camera state on Android, converts it to a neutral project-owned model, and exposes it through a renderer-facing contract only.

## Goal
Introduce a minimal Android-only camera observation adapter for MapLibre so camera values can be obtained as neutral snapshots without binding the renderer to business logic.

## Non-Goals
- No business logic redesign
- No navigation or Decompose redesign
- No DI framework introduction
- No broad feature API redesign
- No MapLibre feature expansion beyond reading camera values
- No write-back camera control in this ticket
- No shared/core abstraction unless minimally required

## User Scenarios
- Scenario 1: A developer can obtain current camera values after map interaction without using MapLibre types outside Android code.
- Scenario 2: A developer can observe stable camera updates without putting listener logic into composables.
- Scenario 3: A future feature can consume camera snapshots if needed, but camera observation itself remains business-agnostic.
- Scenario 4: A user interacts with the map and existing visual behavior remains unchanged.

## Acceptance Criteria
- [ ] Camera observation stays only in `androidMain`
- [ ] No `MapLibreMap`, `CameraPosition`, `LatLng`, or MapLibre listener types leak into `commonMain`
- [ ] Camera values are exposed through a neutral project-owned snapshot model
- [ ] Camera listener registration is lifecycle-safe and bound to existing map ownership
- [ ] Camera observation logic is separated from style application and `MapView` lifecycle orchestration
- [ ] Composables do not own MapLibre listener registration logic
- [ ] Default camera read strategy uses a stable callback point and avoids excessive update churn
- [ ] Existing map behavior remains unchanged
- [ ] The design follows SOLID and keeps camera observation independent from business logic

## Constraints
- Follow `AGENTS.md`
- Keep the change minimal
- Respect KMP-first architecture
- Keep Compose UI-only
- Keep MapLibre Android-specific
- Do not place business logic in renderer code
- Avoid unnecessary abstractions and package churn

## Success Metrics
- Camera values can be read without leaking platform types
- Camera observation is isolated and easy to extend
- Renderer remains thin and platform-focused
- Minimal relevant verification passes

## Technical Notes
- Obtain `MapLibreMap` only after `getMapAsync(...)`
- Read and modify `MapLibreMap` only on the main thread
- `getCameraPosition()` returns a snapshot and does not auto-update
- Prefer `OnCameraIdleListener` as the default stable read path
- Do not use `OnCameraMoveListener` by default unless continuous tracking is explicitly needed
