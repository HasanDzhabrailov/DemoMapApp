# MAP-010 - Add map controls overlay and settings menu

## Context
The map screen currently supports map rendering, center-driven point creation, line and polygon drawing, and shared feature info windows.

The next step is to add a minimal controls overlay inspired by the provided reference:
- a settings button in the bottom-left corner
- zoom controls in the bottom-right corner
- a settings popup menu with placeholder actions

This change must preserve the current KMP-first architecture:
- shared UI and state stay in `commonMain`
- MapLibre integration stays Android-specific
- renderer code remains free of business logic

## Goal
Add a minimal map controls overlay and settings menu to the map screen, with real zoom behavior and placeholder menu actions, while preserving all existing map flows.

## Non-Goals
- No real GPS/current-location implementation
- No location permission handling
- No camera follow-my-location behavior
- No Android location service integration
- No real ruler/measurement implementation
- No real map source selection flow
- No real "maps on screen" flow
- No custom compass asset or compass redesign
- No broad refactor of the map feature
- No changes to point, line, polygon, or feature info product behavior beyond necessary overlay coordination

## Functional Requirements
- Show a settings button in the bottom-left corner of the map screen
- Show `+` and `-` zoom controls in the bottom-right corner of the map screen
- Pressing `+` increases map zoom
- Pressing `-` decreases map zoom
- Pressing the settings button opens a popup menu
- Tapping outside the popup closes the menu
- The popup menu contains:
  - `Доступные карты`
  - `Карты на экране`
  - `GPS`
  - `Рулетка`
- Pressing `Доступные карты` closes the menu and performs no other logic yet
- Pressing `Карты на экране` closes the menu and performs no other logic yet
- `GPS` acts as a UI toggle and does not close the menu
- `Рулетка` acts as a UI toggle and does not close the menu
- The default MapLibre compass remains in use

## Acceptance Criteria
- [ ] A settings button is visible in the bottom-left corner
- [ ] `+` and `-` zoom controls are visible in the bottom-right corner
- [ ] `+` and `-` change map zoom on Android
- [ ] Zoom uses built-in MapLibre camera update functions when available
- [ ] A fallback uses standard MapLibre camera update APIs only if direct zoom-in/zoom-out helpers are unavailable in the current SDK
- [ ] The settings popup opens from the settings button
- [ ] The settings popup closes on outside tap
- [ ] `Доступные карты` closes the menu
- [ ] `Карты на экране` closes the menu
- [ ] `GPS` toggles on/off without closing the menu
- [ ] `Рулетка` toggles on/off without closing the menu
- [ ] `GPS` only changes placeholder UI state
- [ ] No location permissions are requested
- [ ] No current-location lookup is performed
- [ ] No camera movement is triggered by the `GPS` toggle
- [ ] Opening the settings menu closes the center marker menu if it is visible
- [ ] Opening the settings menu closes the selected feature info window if it is visible
- [ ] Opening the center marker menu closes the settings menu if it is visible
- [ ] Clicking a rendered feature closes the settings menu if it is visible
- [ ] Existing point, line, polygon, preview, and feature info flows remain unchanged
- [ ] MapLibre-specific zoom execution remains only in `androidMain`

## Constraints
- Follow `AGENTS.md`
- Keep the change minimal and within the map business area
- Keep Compose UI-only
- Keep state outside composables
- Keep MapLibre Android-specific
- Do not place business logic in renderer code
- Respect KMP-first architecture
- Do not add unnecessary dependencies for zoom controls
- Use text `+` and `-` controls unless a dependency-free built-in icon path already exists in the project
- Do not mix future GPS/current-location business logic into this ticket

## Success Metrics
- The map screen exposes the requested controls without breaking current map behavior
- Android zoom works through MapLibre camera APIs
- Placeholder menu items behave as specified
- `GPS` remains a UI-only placeholder in this ticket
- Minimal relevant verification passes
