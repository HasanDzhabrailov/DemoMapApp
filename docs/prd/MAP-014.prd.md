# MAP-014 - Define explicit MapScreen Intent, State, and Label contracts

## Context
`MAP-013` introduced the initial MVIKotlin store skeleton for the map feature. The next step is to define the explicit Store contracts that will become the new center of screen logic.

The current `MapScreenComponent` API still exposes many `onXxx` methods and nested DTOs. The migration should begin by introducing clear Store-level contracts without breaking existing behavior.

## Goal
Define explicit MVIKotlin contracts for `MapScreen`:
- `Intent`
- `State`
- `Label`

and start mapping the current callback API toward these contracts while preserving the current Decompose component surface.

## Non-Goals
- No broad reducer migration yet
- No executor-heavy migration yet
- No renderer refactor
- No removal of old `onXxx` APIs yet
- No behavior change

## Functional Requirements
- Introduce a dedicated map screen Store contract with:
  - explicit `Intent`
  - explicit `State`
  - explicit `Label`
- Map current component callbacks conceptually to Store intents
- Define Store state so it can replace `MapScreenComponent.Model` incrementally
- Preserve current behavior and current UI contract during this ticket
- Keep one-time events represented in a way that can be migrated safely later

## Acceptance Criteria
- [ ] A full internal `MapStore.Intent` contract exists
- [ ] A full internal `MapStore.State` contract exists
- [ ] A full internal `MapStore.Label` contract exists
- [ ] Existing `onXxx` component callbacks can be mapped to Store intents
- [ ] No public behavior changes are introduced
- [ ] The new contracts are usable by later reducer/executor migration tickets

## Constraints
- Follow `AGENTS.md`
- Keep migration incremental
- Do not break Compose screen usage
- Do not rewrite screen state management in one ticket

## Success Metrics
- `MapScreen` has explicit MVIKotlin vocabulary
- Future tickets can move logic to reducer/executor without redesigning the contracts
- The component surface can become thinner later without blocking this step
