# MAP-024 - Finalize responsibility-first MVIKotlin map architecture and update AGENTS.md rules

## Context
The preceding migration tickets move the map feature toward MVIKotlin integrated with Decompose and reduce responsibility violations across the component, Store, UI, and renderer. The final step is to remove remaining fake-MVI patterns, confirm the target architecture, and codify the new rules in `AGENTS.md` and ticketing guidance.

This ticket should formalize the responsibility-first architecture so future feature work does not recreate god files or mix concerns again.

## Goal
Finalize the map feature migration and update project rules so that:
- Store is the center of screen logic
- component is a thin Decompose wrapper
- reducer is pure
- executor owns side effects
- UI is render-only and intent-sending
- renderer is platform-specific and rendering-only
- responsibility-first splitting rules are explicit in `AGENTS.md`

## Non-Goals
- No broad rewrite outside the current feature/business area
- No architectural novelty beyond MVIKotlin + Decompose target
- No unnecessary abstraction layers

## Functional Requirements
- Remove or reduce remaining fake-MVI patterns in the map feature
- Confirm the target responsibility ownership for:
  - component
  - Store
  - reducer
  - executor
  - label
  - UI
  - renderer
- Update `AGENTS.md` with:
  - responsibility-first rule
  - mandatory MVIKotlin screen structure
  - reducer/executor/UI restrictions
  - anti-pattern guidance
  - file responsibility rule
  - new feature rules
- Keep behavior unchanged

## Acceptance Criteria
- [ ] Remaining fake-MVI patterns in the map feature are reduced or documented for follow-up
- [ ] Final map architecture matches responsibility-first MVIKotlin direction
- [ ] `AGENTS.md` is updated with the new architecture rules
- [ ] Existing behavior remains unchanged
- [ ] Future work has explicit rules to avoid responsibility regressions

## Constraints
- Follow `AGENTS.md`
- Keep changes scoped to the current ticket and business area plus justified architecture rule updates
- Do not rewrite the project
- Preserve behavior

## Success Metrics
- Responsibility ownership is explicit and enforceable
- Store is the stable center of map screen logic
- Future features can be implemented without recreating god components or mixed-responsibility files
