# MAP-001 — Add MapLibre rendering via AndroidView without business logic

## Context
The project needs map display support.
MapLibre must be used as a rendering layer only.
Platform-dependent MapLibre code must stay in Android-specific source sets.

## Goal
Add MapLibre map rendering to the project using `AndroidView`.

## Non-Goals
- No business logic inside map rendering code
- No platform-specific MapLibre code in `commonMain`
- No state ownership inside composables
- No feature redesign beyond the minimal map rendering integration
- No new DI framework
- No map-related domain layer introduction

## User Scenarios
- Scenario 1: A user opens a screen with a map and sees the map rendered correctly.
- Scenario 2: A developer can work with the map UI without mixing business logic into MapLibre integration.
- Scenario 3: Shared business logic remains platform-agnostic and does not depend on MapLibre Android APIs.

## Acceptance Criteria
- [ ] MapLibre map is rendered on Android using `AndroidView`
- [ ] All MapLibre platform-dependent code is placed in `androidMain` or Android-specific modules only
- [ ] No business logic is placed in map rendering code
- [ ] Composables remain UI-only and emit events only
- [ ] No side effects are launched from the composable body
- [ ] `commonMain` does not depend on Android MapLibre APIs

## Constraints
- Follow `AGENTS.md`
- Keep the change minimal
- Respect KMP-first architecture
- Respect platform boundaries and existing module boundaries
- MapLibre is rendering only

## Success Metrics
- Map screen renders correctly on Android
- No platform-specific leakage into shared business logic
- Verification commands pass

## Open Questions
- Is a small UI adapter needed between shared UI contract and Android map rendering?
- Should the initial map configuration be passed as pure UI parameters from outside the renderer?
