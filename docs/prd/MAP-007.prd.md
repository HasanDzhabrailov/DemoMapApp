# MAP-007 - Center marker, create-point draft flow, and point info window

## Context
The map feature already keeps MapLibre rendering Android-specific and exposes neutral renderer inputs in shared code. The ticket evolved from a fixed center marker into the minimal end-to-end point flow needed for this screen: select map center, draft a point, create it on confirm, render created points, and open an info window for an existing point.

## Goal
Complete the minimal map point interaction flow while preserving strict render/business separation:
- keep a fixed center marker in shared UI
- store the latest neutral camera snapshot in screen state
- create points only through the screen/component flow
- render created points through a neutral render model
- open a shared Compose info window near a clicked point showing title and creation date

## Non-Goals
- No point editing or deletion
- No details screen
- No clustering or advanced map interactions
- No renderer business logic
- No MapLibre API leakage into shared business state
- No DI framework introduction

## User Scenarios
- Scenario 1: A user moves the map and sees a fixed marker at screen center.
- Scenario 2: After camera idle, the latest center coordinate is stored for product use.
- Scenario 3: A user opens a create-point flow from the center marker and confirms a point draft.
- Scenario 4: A created point appears on the map with its title.
- Scenario 5: A user taps an existing point and sees an info window anchored near that point with title and creation date.
- Scenario 6: Existing map behavior remains render-focused and platform-separated.

## Acceptance Criteria
- [x] The center marker is displayed above the map and remains visually fixed at screen center.
- [x] The marker is implemented in shared UI, not in Android renderer code.
- [x] Camera snapshots remain renderer output only.
- [x] The latest camera snapshot used for product behavior is stored outside debug-only state.
- [x] The create-point draft flow is screen/component driven and creates a point only on explicit confirm.
- [x] Created points are stored in minimal map feature state and rendered through a neutral render model.
- [x] Tapping an existing point opens an info window near the point with title and creation date.
- [x] The renderer exposes only a neutral click seam and does not depend on `MapPoint`, `MapState`, or product semantics.
- [x] Android-only hit detection and MapLibre click integration stay in `androidMain`.
- [x] No business logic is added to `MapRenderer` or `MapLibreCameraAdapter`.
- [x] Existing map behavior remains unchanged outside this minimal flow.
- [x] The design follows SOLID and preserves render/business separation.

## Constraints
- Follow `AGENTS.md`
- Keep the change minimal and within the map business area
- Keep Compose UI-only
- Keep MapLibre Android-specific
- Do not place business logic in renderer code
- Respect KMP-first architecture
- Keep source of truth for selected-point/info-window flow only in `MapScreenComponent.Model`

## Success Metrics
- Users can understand the currently selected center coordinate.
- Users can create a point from the current center snapshot.
- Users can tap a rendered point and read its basic metadata.
- The renderer remains thin, neutral, and platform-focused.
- Minimal relevant verification passes.

## Technical Notes
- Keep the fixed center marker as a Compose overlay in screen UI.
- Use `onCameraIdle` as the stable center coordinate source.
- Keep point identity explicit in business state so renderer selection does not depend on derived field combinations.
- Keep point click output neutral, limited to renderer key and screen anchor.
- Show the info window in shared Compose UI, not inside MapLibre-native renderer code.
