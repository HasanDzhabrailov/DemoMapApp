# MAP-007 — Add fixed center selection marker for future geo-object creation

## Context
The map renderer already exposes neutral camera snapshots through an Android-only observation adapter without leaking MapLibre types into shared code.

The next step is to help the user understand which coordinate is selected for future geo-object creation by showing a fixed marker at the visual center of the map screen.

This marker must remain a UI overlay and must not introduce business logic into the renderer layer.

## Goal
Add an always-visible center marker overlay above the map so the user can visually select the future geo-object location, while keeping map rendering platform-focused and business-agnostic.

## Non-Goals
- No geo-object creation flow implementation
- No menu implementation yet
- No renderer business logic
- No continuous camera tracking during movement
- No MapLibre API leakage into shared code
- No navigation redesign
- No DI framework introduction

## User Scenarios
- Scenario 1: A user moves the map and sees a fixed marker in the center of the screen.
- Scenario 2: After the camera stops, the app stores the center camera coordinate as the selected future geo-object position.
- Scenario 3: A future feature can open a creation menu when the user taps the center marker.
- Scenario 4: Existing map rendering behavior remains unchanged.

## Acceptance Criteria
- [ ] The center marker is displayed above the map and remains visually fixed at screen center
- [ ] The marker is implemented in shared UI, not in Android renderer code
- [ ] Camera snapshots remain renderer output only
- [ ] The latest camera snapshot used for future product behavior is stored outside debug-only state
- [ ] A future-facing click seam exists for center marker interaction
- [ ] No business logic is added to `MapRenderer` or `MapLibreCameraAdapter`
- [ ] Existing map behavior remains unchanged
- [ ] The design follows SOLID and preserves render/business separation

## Constraints
- Follow `AGENTS.md`
- Keep the change minimal
- Keep Compose UI-only
- Keep MapLibre Android-specific
- Do not place business logic in renderer code
- Respect KMP-first architecture

## Success Metrics
- Users can visually understand which coordinate is selected
- The renderer remains thin and platform-focused
- Future geo-object creation can reuse the stored center snapshot
- Minimal relevant verification passes

## Technical Notes
- Keep the fixed marker as a Compose overlay in screen UI
- Use the existing `onCameraIdle` snapshot as the source of selected center coordinates
- Do not use continuous camera move callbacks by default
- Prepare a click seam for a future create menu without implementing the menu in this ticket
