# MAP-027 — Refactor UI layer: MapLocationEffectBinder, MapScreenContent, DefaultMapScreenComponent

## Context
Three UI-layer files have grown beyond single responsibility:

1. `MapLocationEffectBinder.android.kt` (243 lines) mixes:
   - Composable effect binding
   - Permission requesting
   - Location resolution
   - Extension functions

2. `MapScreenContent.kt` (281 lines) mixes:
   - Main composable orchestration
   - 7 conditional overlay blocks
   - Preview component
   - Extension functions

3. `DefaultMapScreenComponent.kt` (192 lines) contains:
   - 40+ intent delegation methods
   - Template boilerplate code

## Goal
Split each file into focused, single-responsibility units while preserving behavior.

## Non-Goals
- No behavior changes to location, permission, or UI logic
- No changes to Component API
- No changes to Store/State

## Functional Requirements
- Extract `AndroidLocationResolver` from MapLocationEffectBinder
- Extract `LocationPermissionRequester` from MapLocationEffectBinder
- Thin MapLocationEffectBinder to composable wiring only
- Extract `MapScreenOverlays` from MapScreenContent
- Extract `MapScreenPreview` from MapScreenContent
- Thin MapScreenContent to orchestrator only
- Extract intent delegation helpers from DefaultMapScreenComponent

## Acceptance Criteria
- [ ] AndroidLocationResolver extracted and testable
- [ ] LocationPermissionRequester extracted
- [ ] MapLocationEffectBinder < 60 lines
- [ ] MapScreenOverlays extracted
- [ ] MapScreenPreview extracted
- [ ] MapScreenContent < 80 lines
- [ ] ComponentIntentDelegates extracted
- [ ] DefaultMapScreenComponent < 120 lines
- [ ] All tests pass
- [ ] UI behavior unchanged

## Constraints
- Follow `AGENTS.md`
- Keep Android-specific code in `androidMain`
- Keep UI composables render-only
- Do not place business logic in UI

## Success Metrics

- Each file has single responsibility
- Extension functions isolated
- Preview code isolated from main composable
