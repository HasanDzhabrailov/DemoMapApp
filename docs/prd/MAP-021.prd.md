# MAP-021 - Simplify MapScreenComponent into a thin Decompose wrapper over Store intents

## Context
After migrating the main map workflows into Store-first architecture, `MapScreenComponent` should stop acting as the main home for screen logic. The component should remain part of the Decompose integration, but its role must be reduced to lifecycle ownership, Store holding, and navigation/screen-level bridging.

The current component API still exposes many `onXxx` methods and nested workflow models. This ticket should reduce the component to a thin compatibility wrapper without breaking current behavior.

## Goal
Simplify `MapScreenComponent` so that:
- Decompose component remains the lifecycle and Store holder
- business logic is centered in the Store
- existing UI integrations remain stable during transition
- component API stops growing as the primary place for feature logic

## Non-Goals
- No renderer redesign in this ticket
- No behavior change
- No broad public API redesign outside the map feature
- No large UI rewrite

## Functional Requirements
- Keep Decompose component ownership for the map screen
- Make `DefaultMapScreenComponent` a thin wrapper over Store
- Route existing callback methods to Store intents with minimal local logic
- Remove migrated business logic from the component
- Keep component responsibilities limited to:
  - lifecycle ownership
  - Store ownership
  - navigation/screen-level bridging if needed
  - compatibility wrapper behavior during migration

## Acceptance Criteria
- [ ] `DefaultMapScreenComponent` no longer acts as the primary business-logic engine
- [ ] Existing `onXxx` methods delegate to Store intents with minimal local logic
- [ ] Decompose integration remains intact
- [ ] User-visible behavior remains unchanged
- [ ] The component is materially thinner and easier to describe with one responsibility

## Constraints
- Follow `AGENTS.md`
- Keep migration incremental
- Do not break Decompose integration
- Preserve behavior

## Success Metrics
- `MapScreenComponent` is no longer a god object
- Store becomes the clear center of logic
- New feature work will not append logic blindly into the component
