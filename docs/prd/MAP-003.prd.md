# MAP-003 — Isolate map rendering engine from feature and root layers

## Context
Current map rendering is hidden behind expect/actual, but renderer-owned concerns are still exposed through feature-owned APIs and UI wiring.

The map engine should be responsible only for rendering, while root owns lifecycle/navigation and feature owns screen/business state.

## Goal
Refactor map layering so feature/root layers stay library-agnostic and the map library remains an Android-specific rendering engine only.

## Non-Goals
- No business logic changes
- No navigation redesign
- No MapLibre API expansion
- No new DI framework
- No broad module split
- No shared/core refactor beyond minimal required changes

## User Scenarios
- Scenario 1: A user opens the app and sees the same map behavior as before.
- Scenario 2: A developer can trace root ownership separately from rendering ownership.
- Scenario 3: Shared feature code contains no direct MapLibre-oriented concerns.

## Acceptance Criteria
- [ ] `MapScreenContent` does not depend on `RootComponent.Child.MapScreen`
- [ ] Renderer contract is not owned by `feature.map.api`
- [ ] Shared feature state does not expose MapLibre-specific rendering details unless strictly required by product semantics
- [ ] Android-specific MapLibre code remains only in `androidMain`
- [ ] Existing map rendering behavior remains unchanged
- [ ] No business logic is added to map rendering code

## Constraints
- Follow `AGENTS.md`
- Keep the change minimal
- Respect KMP-first architecture
- Keep Compose UI-only
- Keep MapLibre as render layer only
- Touch shared/core code only if minimally required

## Success Metrics
- Android map screen still works
- Root/feature/render responsibilities are clearer
- Shared feature code is more library-agnostic
- Minimal relevant verification passes

## Open Questions
- Should the default map style be resolved entirely in the render layer, or represented as a feature-level style id?
- Should feature-to-render mapping live in component impl or in a dedicated render boundary adapter?
