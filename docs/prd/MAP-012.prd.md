# MAP-012 - Add ruler measurement mode from current or fallback manual location

## Context
MAP-010 added the map controls overlay and settings menu, including a placeholder `Рулетка` toggle.

MAP-011 added real current-location behavior and a shared `currentLocationMarker` that can represent:
- a real GPS location
- a manual placeholder location when GPS is not active

The next step is to turn `Рулетка` into a real measurement mode that builds a line from the user's current location to the current map center and shows a dedicated information window with measurement data.

## Goal
Add a real ruler measurement mode to the map screen with:
- a working `Рулетка` toggle in the existing settings menu
- a measurement line from the user's current location to the current map center
- automatic fallback to manual location if no current location exists yet
- a dedicated ruler information window with measurement data

## Non-Goals
- No continuous GPS tracking
- No background/service logic
- No persistence of ruler measurements
- No storing ruler geometry in `MapState.lines`
- No redesign of existing menu, zoom, compass, GPS, or shape creation flows
- No broad refactor outside the map feature
- No requirement in this ticket to implement final magnetic azimuth or directional angle formulas unless they are already fully defined

## Functional Requirements
- Keep the existing `Рулетка` item inside the settings popup menu
- `Рулетка` acts as a real on/off toggle and does not close the menu

- When `Рулетка` is turned on:
  - determine the measurement start point from the current user location
  - if a real GPS location marker exists, use it as the start point
  - otherwise, if a manual location marker exists, use it as the start point
  - otherwise, if a camera snapshot is available, create a manual placeholder location marker at the current map center and use it as the start point
  - otherwise, wait until the first camera snapshot becomes available and then create the fallback manual placeholder location marker

- While ruler mode is active:
  - use the current map center as the measurement end point
  - show a temporary measurement line between the start point and the current map center
  - update the end point and calculated values when the camera changes
  - show a dedicated ruler information window on top of the map
  - show at least:
    - distance
    - true azimuth `A`
  - allow the information model to be extended later for:
    - magnetic azimuth `Ам`
    - directional angle `α`

- When `Рулетка` is turned off:
  - turn ruler mode off
  - hide the temporary measurement line
  - hide the ruler information window
  - clear temporary ruler calculation state

- Ruler behavior must use the existing current-location/manual-location flow as the source of the start point
- If GPS later resolves a real location while ruler mode is active, the ruler start point should switch to the latest real current location
- If the user updates manual location while ruler mode is active and GPS is not active, the ruler start point should follow that manual location

- The ruler measurement line must be rendered separately from user-created lines
- The ruler measurement line must not open the shared feature info window
- Existing point, line, polygon, preview, GPS, my-location, zoom, and menu flows must remain intact

## Acceptance Criteria
- [ ] The existing `Рулетка` menu item triggers real ruler mode
- [ ] Turning `Рулетка` on uses the GPS current-location marker when it exists
- [ ] Turning `Рулетка` on uses the manual location marker when GPS location does not exist but manual location does
- [ ] Turning `Рулетка` on creates a manual placeholder location marker at the current map center when no current location marker exists and a camera snapshot is available
- [ ] If no camera snapshot exists yet, ruler mode waits and creates the fallback manual placeholder marker after the first snapshot arrives
- [ ] A temporary measurement line is visible while ruler mode is active
- [ ] The measurement end point follows the current map center
- [ ] Distance is recalculated when the camera changes
- [ ] True azimuth `A` is recalculated when the camera changes
- [ ] A dedicated ruler information window is visible while ruler mode is active
- [ ] The ruler information window shows at least distance and `A`
- [ ] Turning `Рулетка` off hides the temporary line and ruler information window
- [ ] The ruler measurement is not stored in `MapState.lines`
- [ ] The ruler measurement does not open the shared feature info window
- [ ] Existing point, line, polygon, preview, GPS, my-location, zoom, and menu flows remain unchanged
- [ ] MapLibre-specific rendering remains Android-specific
- [ ] No background/service logic is introduced

## Constraints
- Follow `AGENTS.md`
- Keep the change minimal and within the map business area
- Keep Compose UI-only
- Keep state outside composables
- Keep business calculations in shared code where possible
- Keep MapLibre integration Android-specific
- Do not place business logic in renderer code
- Respect KMP-first architecture
- Prefer transient screen/render state over storing ruler data in persistent map feature data
- Do not introduce unnecessary dependencies

## Success Metrics
- Ruler mode works from GPS or fallback manual location
- The map shows a live measurement line to the current map center
- The information window shows useful ruler data without breaking current flows
- Minimal relevant verification passes
