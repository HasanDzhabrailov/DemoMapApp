# MAP-019 - Migrate line and polygon drawing flow to Store-first MVIKotlin architecture

## Context
The shape drawing flow includes start actions, draft vertex updates, preview behavior, details sheet gating, title editing, and final line/polygon creation. These responsibilities are currently coordinated in `DefaultMapScreenComponent`, with some helper extraction already present.

This flow has enough branching to benefit from explicit Store ownership, but it should be migrated incrementally without redesigning rendering or screen UI.

## Goal
Move line and polygon drawing workflows into Store-first architecture so that:
- Store state owns drawing mode and draft
- reducer owns pure draft transitions
- executor owns confirm-time creation orchestration
- component becomes thinner
- behavior remains unchanged

## Non-Goals
- No redesign of drawing controls
- No renderer redesign
- No migration of feature selection flow in this ticket
- No broad public API cleanup yet

## Functional Requirements
- Represent line/polygon drawing interactions through explicit Store intents
- Move drawing mode activation and dismiss transitions into reducer
- Move add/remove vertex transitions into reducer or reducer-driven state path using existing helpers
- Preserve preview behavior and current render model mapping
- Preserve details gating based on minimum vertex counts
- Move confirm-time line/polygon creation into executor using existing use cases
- Preserve current behavior for:
  - line start
  - polygon start
  - add/remove positions
  - details open only when valid
  - title editing
  - successful line/polygon creation
  - draft reset after completion/dismissal

## Acceptance Criteria
- [ ] Drawing flows are driven through explicit Store intents
- [ ] Pure draft transitions are reducer-owned
- [ ] Confirm-time feature creation is executor-owned
- [ ] Existing preview/render behavior remains unchanged
- [ ] Existing line/polygon workflows remain unchanged for users

## Constraints
- Follow `AGENTS.md`
- Keep renderer logic renderer-only
- Keep validation/gating out of UI where possible
- Keep migration incremental

## Success Metrics
- Shape drawing is no longer coordinated primarily in the component
- Drawing state has clear Store ownership
- Future drawing enhancements can be added without creating new god methods
