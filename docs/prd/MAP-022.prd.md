# MAP-022 - Decouple Store and helper models from MapScreenComponent contract

## Context
Several helper classes and mappers currently depend on nested models declared inside `MapScreenComponent`, such as shape drafts and info window DTOs. This couples lower-level workflow logic to the component contract and makes the component a hidden dependency center.

After Store-first migration is in place, these contracts should be separated so that helpers depend on Store/domain-oriented models instead of component-owned types.

## Goal
Decouple Store and helper logic from `MapScreenComponent` nested models so that:
- component contract stops owning unrelated workflow DTOs
- helper classes depend on dedicated Store or feature models
- responsibility boundaries become cleaner
- future refactors are easier and safer

## Non-Goals
- No behavior change
- No renderer redesign
- No broad package rewrite beyond the map feature
- No unnecessary model explosion

## Functional Requirements
- Identify helper classes and mappers that depend on `MapScreenComponent` nested types
- Introduce dedicated Store/feature-level models where needed
- Remove unnecessary dependencies on `MapScreenComponent` nested DTOs
- Preserve current behavior and rendering/UI output
- Keep the change minimal and responsibility-driven

## Acceptance Criteria
- [ ] Helper classes no longer depend unnecessarily on `MapScreenComponent` nested models
- [ ] Store-related models are owned by Store/feature-level packages
- [ ] Component contract is less coupled and easier to describe
- [ ] Existing behavior remains unchanged

## Constraints
- Follow `AGENTS.md`
- Split by responsibility, not by file size
- Keep model count minimal and justified
- Preserve behavior

## Success Metrics
- `MapScreenComponent` stops acting as a hidden shared model namespace
- Store/helper boundaries are cleaner
- Future migration work can happen without touching component-owned DTOs unnecessarily
