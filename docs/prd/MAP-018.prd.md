# MAP-018 - Migrate create-point flow to Store-first MVIKotlin architecture

## Context
The create-point flow already has separated input validation in `CreateMapPointUseCase`, but the workflow itself is still coordinated through `DefaultMapScreenComponent`. Draft editing, sheet visibility, confirm action, and state mutation are not yet centered on the Store.

This ticket should migrate point creation to responsibility-driven MVIKotlin structure while preserving current behavior.

## Goal
Move create-point workflow ownership into the Store so that:
- UI renders draft state and sends intents
- reducer owns pure draft and visibility transitions
- executor owns confirmation-time side effects and use-case invocation
- component becomes thinner
- behavior remains unchanged

## Non-Goals
- No redesign of point creation UI
- No migration of line/polygon creation in this ticket
- No renderer redesign
- No new validation framework

## Functional Requirements
- Represent create-point interactions through explicit Store intents
- Move create-point sheet visibility and draft field updates into reducer-driven transitions
- Keep coordinate parsing/validation in `CreateMapPointUseCase`
- Move confirm-time point creation orchestration into executor
- Preserve current behavior:
  - point draft initialization from current camera snapshot
  - latitude/longitude/title editing
  - no point creation on invalid input
  - point added to `MapState.points` on successful confirmation
  - sheet dismissed and draft cleared after successful creation

## Acceptance Criteria
- [ ] Create-point flow is driven through explicit Store intents
- [ ] Draft visibility and field updates are reducer-owned
- [ ] Point creation confirm flow is executor-owned
- [ ] Validation remains outside UI
- [ ] Existing create-point behavior remains unchanged
- [ ] Existing tests continue to pass or are updated to the new architecture boundaries

## Constraints
- Follow `AGENTS.md`
- Keep validation out of UI
- Keep migration incremental
- Do not change point feature behavior

## Success Metrics
- Point creation no longer depends on component-local workflow orchestration
- Validation remains clearly separated
- Future point-related enhancements can extend the Store cleanly
