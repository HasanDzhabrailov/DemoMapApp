# MAP-030 — Manage tile-based map layers from map settings

## Context
The map screen already contains entry points for `Available maps` and `Maps on screen`, but both actions are placeholders and only close the tools menu.

The product needs:
- a list of available maps in settings
- ability to add a selected map layer to the current map
- a bottom sheet with currently loaded layers
- ability to change layer opacity
- ability to remove a layer
- ability to move a layer up/down

Current implementation supports only one base style and app-owned geometry overlays.

## Goal
Add map layer management to the map screen while preserving current MVI structure and keeping MapLibre-specific logic isolated in Android renderer code.

## Non-Goals
- No provider SDK integration
- No full offline cache manager in this ticket
- No background downloads
- No Room persistence unless minimally required
- No broad map feature refactor outside minimal required scope
- No licensing automation for external providers

## Functional Requirements
- Show `Available maps` from the map tools menu
- Show a static catalog of available map sources:
  - DEM map (open-source base style)
  - OpenStreetMap raster tiles
  - Google raster tile template
  - Yandex raster tile template
- Do not use Google or Yandex SDKs
- All external maps must be integrated through tile-based sources only
- Ask for confirmation before adding a map layer
- Show `Maps on screen` bottom sheet with loaded layers
- Allow for each loaded layer:
  - move up
  - move down
  - change opacity
  - remove layer
- Keep one active base map at a time
- Support additional overlay layers above the base map
- Normalize map sources through a conversion layer into renderer-compatible tile/style descriptors
- Unsupported source must fail safely without crashing UI

## Acceptance Criteria
- [ ] `Available maps` opens a screen or bottom sheet with catalog entries
- [ ] Selecting a catalog item opens confirmation UI
- [ ] Confirming adds the layer to map state and renderer input
- [ ] `Maps on screen` shows ordered loaded layers
- [ ] Layer can be moved up/down within allowed bounds
- [ ] Layer opacity can be changed and reflected on map
- [ ] Layer can be removed from loaded list and renderer
- [ ] Existing map tools, GPS, ruler, and feature drawing behavior remain working
- [ ] Map source conversion keeps current render flow intact
- [ ] No Google or Yandex SDK is added

## Constraints
- Follow `AGENTS.md`
- KMP-first: product state and UI state in `commonMain`
- Android-specific provider/render details only in `androidMain`
- Component is lifecycle/navigation only
- Reducer must stay pure
- Executor owns all side effects
- MapLibre remains rendering only
- No provider SDK integration
- External providers must be connected only through tile URLs/templates supported by renderer
- Provider-specific URLs, attribution, and request params must stay outside reducer/UI
- Keep changes minimal and scoped to map feature

## Success Metrics
- User can add and manage map layers without leaving map screen
- Current single-style rendering path remains backward compatible
- No business logic leaks into Compose UI or renderer

## Open Questions
- Should loaded layers persist between app launches, or remain session-only in first version?
- Should switching base map replace the previous base map automatically?
- Which Google/Yandex tile templates and attribution rules are allowed for the target release environment?

## Risks
- Google and Yandex tile endpoints may have usage, attribution, or legal restrictions
- Current renderer assumes a single style and will need a backward-compatible extension
- Incorrect separation between product models and renderer descriptors may leak render logic into common code
