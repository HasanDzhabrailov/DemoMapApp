# MAP-026 - Refactor MapRenderStyleAppliers by responsibility

## Context
`MapRenderStyleAppliers.android.kt` (432 lines) contains all style appliers for:
- Points (applyPoints)
- Lines (applyLines)
- Polygons (applyPolygons)
- Ruler measurement (applyRulerMeasurement)
- Drawing preview (applyDrawingPreview)
- Current location marker (applyCurrentLocationMarker)

This violates single responsibility and makes the file harder to navigate/maintain.

## Goal
Split `MapRenderStyleAppliers.android.kt` into focused applier files:
- `PointStyleApplier.android.kt`
- `LineStyleApplier.android.kt`
- `PolygonStyleApplier.android.kt`
- `RulerStyleApplier.android.kt`
- `DrawingPreviewApplier.android.kt`
- `CurrentLocationStyleApplier.android.kt`
- Shared constants/constants file

## Non-Goals
- No changes to rendering behavior
- No changes to MapLibre styling values
- No changes to caller code (MapRenderer.android.kt)

## Functional Requirements
- Extract each applier function to its own file
- Shared constants (layer IDs, source IDs) moved to shared file or kept internal
- Extension function `RenderMapStyle.styleUrl()` stays or moves to appropriate file
- Helper functions (`closedRing`, `toGeometryPoint`) co-located with their primary user

## Acceptance Criteria
- [ ] Each applier in its own file under `render/` package
- [ ] Original file removed or reduced to imports/consts only
- [ ] All existing tests pass
- [ ] No behavior changes in map rendering
- [ ] ktlint/detekt pass

## Constraints
- Follow `AGENTS.md`
- Keep MapLibre integration Android-specific (`androidMain`)
- Do not place business logic inside map rendering code
- Split files only when responsibilities diverge

## Success Metrics
- Each file < 120 lines
- Files are independently understandable
- Future appliers can be added without touching existing files

## Open Questions
- Should `RenderMapStyle.styleUrl()` go into a separate `StyleUrls.android.kt` or stay shared?
- Which file should own the helper extensions (`closedRing`, `toGeometryPoint`)?
