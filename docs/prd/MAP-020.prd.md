# MAP-020 - Migrate feature selection and info window flow to Store-first MVIKotlin architecture

## Context
Feature selection and info window behavior currently depend on component-local orchestration. Renderer clicks are translated in UI, resolved through helper classes, and then committed into screen state in the component.

This flow should be migrated into Store-first ownership so that feature selection becomes a clean responsibility group with explicit intents, reducer transitions, and executor-driven lookup/orchestration where needed.

## Goal
Move feature selection and info window flow into Store-first architecture while preserving current behavior.

## Non-Goals
- No redesign of info window UI
- No renderer redesign beyond minimal integration changes
- No broad public API cleanup yet
- No migration of unrelated flows in this ticket

## Functional Requirements
- Represent feature click and info-window dismiss behavior through explicit Store intents
- Preserve mapping from renderer click to feature selection flow
- Preserve feature resolution from `MapState`
- Preserve feature info window state mapping
- Preserve existing behavior:
  - clicking point/line/polygon opens the shared feature info window
  - ruler measurement does not use this shared info flow
  - opening conflicting overlays still behaves consistently
  - dismiss closes the shared feature info window

## Acceptance Criteria
- [ ] Feature selection flow is driven through explicit Store intents
- [ ] Feature selection state transitions are reducer-owned where pure
- [ ] Feature lookup/orchestration is executor-owned where appropriate
- [ ] Existing shared feature info window behavior remains unchanged
- [ ] Ruler remains excluded from shared feature info behavior

## Constraints
- Follow `AGENTS.md`
- Keep renderer Android-specific
- Do not put business logic in renderer
- Keep migration incremental

## Success Metrics
- Feature selection becomes its own responsibility group
- Component logic is reduced further
- Selection and info window behavior can evolve without growing the component
