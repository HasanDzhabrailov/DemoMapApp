# MAP-015 - Move simple MapScreen state transitions into a pure Reducer

## Context
`MAP-014` defines explicit Store contracts for `MapScreen`. The next safe migration step is to move simple synchronous state transitions into a pure reducer.

The current logic in `DefaultMapScreenComponent` still performs direct state mutation across many handlers. This ticket should move only low-risk, side-effect-free transitions first.

## Goal
Introduce a pure reducer for `MapScreen` and migrate simple state transitions into it, while preserving behavior.

## Non-Goals
- No migration of asynchronous or platform side effects yet
- No migration of all workflows in one ticket
- No renderer refactor
- No public API removal yet

## Functional Requirements
- Introduce a pure reducer for map screen Store state
- Move low-risk synchronous transitions into the reducer first
- Keep side effects out of the reducer
- Preserve current behavior and existing UI interactions
- Keep remaining non-migrated flows working through compatibility paths if needed

## Scope for This Ticket
Preferred reducer-first migrations:
- map tools menu visibility
- center marker menu visibility
- create-point sheet visibility toggles
- shape details sheet visibility toggles
- simple dismiss actions
- local draft text changes
- other synchronous view-state transitions that do not require IO or platform access

## Acceptance Criteria
- [ ] A pure reducer exists for `MapScreen`
- [ ] Simple synchronous transitions are handled via reducer messages/results
- [ ] Reducer performs no side effects
- [ ] Existing behavior remains unchanged
- [ ] Non-migrated flows still work safely through compatibility code

## Constraints
- Follow `AGENTS.md`
- Reducer must remain pure
- Do not move platform or async work into reducer
- Keep migration incremental and low risk

## Success Metrics
- The map feature now has a real reducer center for simple transitions
- The component becomes thinner for migrated scenarios
- Future logic migration has a stable pure transition layer
