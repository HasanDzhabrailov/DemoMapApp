# Plan - MAP-018

## Summary
Migrate the create-point workflow into Store-first MVIKotlin architecture. Keep validation in the existing use case, but move visibility, draft state, and confirm orchestration out of the component.

## Affected Modules
- `feature/map/api`
- `feature/map/impl`
- internal map store package
- `feature/map/ui`

## File-Level Plan
- Route create-point related callbacks through Store intents
- Move create-point draft state ownership to Store state
- Move create-point draft field updates into reducer
- Move point creation confirm into executor using `CreateMapPointUseCase`
- Preserve current point rendering path through existing state/render mapping

## MVIKotlin Mapping
- Intent:
  - open create-point flow
  - update latitude
  - update longitude
  - update title
  - confirm creation
  - dismiss sheet
- State:
  - `isCreatePointSheetVisible`
  - `createPointDraft`
  - map points collection through overall screen state
- Reducer:
  - open/close sheet
  - initialize draft
  - update draft fields
  - clear draft after success or dismissal
- Executor:
  - invoke `CreateMapPointUseCase`
  - add created point into resulting state path
  - handle confirmation-time orchestration
- Label:
  - likely unnecessary unless a transient effect is needed

## Migration Strategy
1. Inventory current create-point responsibilities in component
2. Route create-point actions through Store intents
3. Move pure draft transitions into reducer
4. Move confirmation-time use-case invocation into executor
5. Preserve current UI contract during migration
6. Verify existing point creation behavior remains unchanged

## Verification
- `./gradlew :composeApp:compileDebugKotlinAndroid`
- `./gradlew :composeApp:compileKotlinJvm`
- `./gradlew :composeApp:test`

## Risks and Mitigations
- Risk: invalid input behavior changes subtly
  - Mitigation: preserve use-case-based validation and scenario tests
- Risk: draft initialization from camera snapshot regresses
  - Mitigation: keep initialization rules explicit in Store flow
- Risk: state clearing after success/dismiss diverges
  - Mitigation: test success and dismissal separately

## Task Breakdown
1. Audit create-point logic in component

3. Move draft initialization and updates to reducer
4. Move confirm orchestration to executor
5. Preserve point addition to `MapState.points`
