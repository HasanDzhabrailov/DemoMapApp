# Plan - MAP-023

## Summary
Refactor `MapRenderer.android.kt` by separating Android/MapLibre concerns into smaller responsibility-focused units while preserving behavior and platform boundaries.

## Affected Modules
- `composeApp/src/androidMain`
- `feature/map/render`

## Likely Responsibility Splits
- Compose renderer entry point
- `MapView` holder / lifecycle / saved state handling
- viewport command application
- render model application orchestration
- style loading / style switching
- points/lines/polygons/ruler/current-location/drawing-preview style appliers
- feature click observation
- camera observation

## File-Level Plan
- Split `MapRenderer.android.kt` into dedicated Android renderer files/classes as justified
- Keep `MapRenderer.kt` public renderer boundary stable if possible
- Reuse existing `MapLibreCameraAdapter` and `MapLibreFeatureClickAdapter`
- Introduce dedicated style applier helpers only where responsibility separation is clear

## Responsibility Rules
Renderer modules may own:
- Android lifecycle integration
- MapLibre source/layer updates
- viewport command application
- click/camera adapter wiring

Renderer modules must not own:
- validation
- feature business rules
- state machine decisions
- Store orchestration

## Migration Strategy
1. Audit current renderer file responsibilities
2. Define clear split boundaries
3. Extract responsibility-focused renderer helpers/files
4. Keep render model and renderer API stable where possible
5. Verify rendering behavior remains unchanged

## Verification
- `./gradlew :composeApp:compileDebugKotlinAndroid`
- `./gradlew :composeApp:compileKotlinJvm`
- `./gradlew :composeApp:test`

## Risks and Mitigations
- Risk: extracting code changes layer/source ordering subtly
  - Mitigation: keep behavior-preserving tests/manual verification focus
- Risk: lifecycle wiring regresses during extraction
  - Mitigation: preserve existing holder responsibilities explicitly
- Risk: file split follows size rather than responsibility
  - Mitigation: extract only clear concern boundaries
