# Plan - MAP-021

## Summary
Reduce `DefaultMapScreenComponent` to a thin Decompose wrapper over the map Store. The goal is not to delete compatibility APIs immediately, but to ensure the component has one clear responsibility.

## Affected Modules
- `feature/map/api`
- `feature/map/impl`
- internal map store package
- `root` integration only if required by constructor wiring

## File-Level Plan
- Refactor `DefaultMapScreenComponent` so it:
  - owns the Store
  - exposes the screen model for UI compatibility
  - delegates current callback methods to `store.accept(...)`
  - observes labels if needed for Decompose/UI bridging
- Keep `MapScreenComponent` interface stable unless a minimal cleanup is safe in this ticket
- Avoid broad API deletion if other code still depends on current shape

## Responsibility Target
Component should own:
- lifecycle
- Store creation/holding
- Decompose integration
- navigation handoff if needed later

Component should not own:
- reducer logic
- workflow orchestration
- validation policy
- side effects
- state mutation rules

## Migration Strategy
1. Audit remaining logic still living inside `DefaultMapScreenComponent`
2. Move any leftover migrated logic into Store paths
3. Replace local branching with direct Store intent delegation
4. Keep compatibility methods as thin wrappers
5. Verify UI behavior remains unchanged

## Verification
- `./gradlew :composeApp:compileDebugKotlinAndroid`
- `./gradlew :composeApp:compileKotlinJvm`
- `./gradlew :composeApp:test`

## Risks and Mitigations
- Risk: some subtle bridging logic still needs to remain in component
  - Mitigation: allow only lifecycle/store-holder logic to stay
- Risk: wrapper methods drift from Store contract
  - Mitigation: keep wrappers minimal and mechanical
- Risk: component model mapping becomes awkward
  - Mitigation: use a clear adapter path until the UI contract is fully updated

## Task Breakdown
1. Audit remaining component-local logic
2. Move remaining migrated logic behind Store boundaries
3. Convert `onXxx` methods into thin Store wrappers
4. Keep Decompose wiring intact
5. Verify behavior is unchanged
6. Run minimal verification
