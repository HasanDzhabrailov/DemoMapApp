# Plan — MAP-006

## Summary
Add a small Android-only camera observation adapter around MapLibre that emits neutral camera snapshots, while keeping listener lifecycle, readiness, and threading concerns inside the renderer layer.

## Affected Modules
- `feature/map/render` common: add a neutral camera snapshot model and minimal renderer output contract
- `feature/map/render` android actual: primary implementation target
- `feature/map/ui`: wire renderer output without adding camera logic
- `feature/map/impl`: no required change unless a later step needs a consumer
- `feature/map/api`: no broad redesign expected

## File-Level Plan
- Add `MapCameraSnapshot` in `commonMain` under `feature/map/render`
- Extend `MapRenderer` contract with a minimal neutral callback such as `onCameraIdle`
- Add Android-only `MapLibreCameraAdapter` in `androidMain`
- Keep `MapRenderer.android.kt` responsible only for wiring adapter lifecycle to existing `MapViewHolder`
- Keep `MapScreenContent` as thin UI wiring only
- Do not route camera data into business state in this ticket

## Implementation Notes
- Keep all MapLibre types and listeners confined to `androidMain`
- Use a project-owned immutable model such as:
  - `latitude`
  - `longitude`
  - `zoom`
  - `bearing`
  - `tilt`
- Register camera listeners only after the map is ready
- Bind listener lifetime to existing holder lifecycle and teardown
- Prefer `OnCameraIdleListener` plus `getCameraPosition()` as the default stable read path
- Keep continuous camera updates out of the default design
- Keep style URL resolution and camera observation as separate responsibilities
- Avoid broad API redesign or extra abstractions without a real consumer

## Proposed Contracts
- `MapCameraSnapshot` in `feature/map/render`
- `MapRenderer(model, modifier, onCameraIdle)`
- Android internal `MapLibreCameraAdapter.attach(map)` / `detach()`

## Risks
- Duplicate listeners if registration is tied to recomposition
- Excessive updates if `OnCameraMoveListener` is used by default
- Platform types leaking into shared code
- Future feedback loops if read and write camera paths are later mixed
- Over-design beyond the minimal ticket scope
