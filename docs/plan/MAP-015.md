# Plan - MAP-015

## Summary
Add a pure reducer for `MapScreen` and migrate only the simplest synchronous state transitions first. This ticket establishes the reducer as the center of state mutation without taking on side-effect-heavy flows.

## Affected Modules
- internal map store package
- `feature/map/impl`
- possibly temporary adapters in `DefaultMapScreenComponent`

## File-Level Plan
- Add reducer-related files such as:
  - `feature/map/impl/store/MapStoreReducer.kt`
  - optional `MapStoreMessage.kt`
- Keep executor minimal or absent for this ticket if not required
- Route selected intents through reducer-managed state transitions
- Keep current compatibility wrapper paths for unmigrated flows

## Candidate Reducer Responsibilities
- menu open/close state
- center marker menu open/close state
- sheet open/close state
- title/latitude/longitude draft field updates
- drawing dismiss/reset state transitions
- simple selection clearing where no side effect is required

## Purity Rules
Reducer must not:
- call use cases
- generate IDs
- read current time
- access platform APIs
- perform async work
- request GPS/location
- trigger map viewport commands directly

## Migration Strategy
1. Add Store messages/results if needed
2. Implement pure reducer over Store state
3. Move simple state-only transitions from component into reducer path
4. Keep old logic wrappers for flows not yet migrated
5. Verify no behavior drift

## Verification
- `./gradlew :composeApp:compileDebugKotlinAndroid`
- `./gradlew :composeApp:compileKotlinJvm`
- `./gradlew :composeApp:test`

## Risks and Mitigations
- Risk: reducer scope expands too aggressively
  - Mitigation: move only low-risk synchronous transitions
- Risk: temporary duplication between old logic and reducer path
  - Mitigation: clearly limit migrated scenarios per responsibility group
- Risk: reducer becomes impure through convenience shortcuts
  - Mitigation: explicitly forbid side effects in reducer implementation

## Task Breakdown
1. Add reducer file(s)
2. Define reducer input message/result model if needed
3. Migrate simple menu visibility transitions
4. Migrate simple sheet visibility transitions
5. Migrate simple draft field updates
6. Keep remaining flows on compatibility path
7. Run minimal verification
