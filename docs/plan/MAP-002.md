# Plan — MAP-002

## Summary
Create a project-owned map facade contract in `feature/map/api`, move MapLibre-specific implementation to Android-only code, and replace direct MapLibre usage outside Android code with facade-based integration.

## Affected Modules
- `feature/map/api`: add facade contract and renderer-facing models if needed
- `feature/map/impl`: use facade contract instead of direct MapLibre dependency
- `composeApp/commonMain`: no MapLibre references allowed
- `composeApp/androidMain`: place AndroidView-based MapLibre facade implementation here if this is the Android integration layer
- `core/common`: no change expected
- `core/ui`: only if a tiny reusable UI render contract is required
- `root/api`: no change expected
- `root/impl`: no change expected
- `root/ui`: no change expected unless wiring is needed

## Implementation Notes
- Define a minimal facade in `feature/map/api`
- Keep facade API render-focused and UI-facing only
- Do not expose MapLibre types through the facade
- Implement the facade with MapLibre only in Android-specific code
- Keep `AndroidView` usage in Android-specific UI code
- Pass state into the renderer from outside
- Emit UI events outward only
- Do not place business logic, orchestration, or decision-making inside facade or renderer
- Avoid broad refactoring

## Risks
- Existing code may directly use MapLibre classes
- Existing UI contracts may depend on Android-specific types
- Facade API may become too wide if not kept render-only

## Verification
- `./gradlew ktlintCheck`
- `./gradlew detekt`
- `./gradlew test`

## Task Breakdown
1. Identify all direct MapLibre references
2. Define a minimal render-only facade contract in `feature/map/api`
3. Implement the MapLibre-backed facade in Android-specific code only
4. Replace direct MapLibre usage with facade usage
5. Ensure no MapLibre or Android types leak into shared code
6. Ensure no business logic is introduced in the facade
7. Run verification
