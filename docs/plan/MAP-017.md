# Plan - MAP-017

## Summary
Migrate the ruler workflow to Store-first architecture. Keep existing calculations and rendering model intact where possible, but move ownership of ruler behavior from component methods into explicit Store intent/reducer/executor flow.

## Affected Modules
- `feature/map/api`
- `feature/map/impl`
- internal map store package
- `feature/map/ui`
- `feature/map/render`

## File-Level Plan
- Add/expand ruler-related Store intent handling
- Move ruler-specific transition logic out of `DefaultMapScreenComponent`
- Reuse existing helpers where appropriate:
  - `RulerMeasurementCalculator`
  - `RulerInfoWindowStateFormatter`
  - `MapRenderModelMapper`
- Keep `MapScreenContent` UI behavior unchanged as much as possible
- Keep renderer integration unchanged except for any contract adjustments needed by Store-first ownership

## MVIKotlin Mapping
- Intent:
  - ruler toggle
  - camera snapshot update
  - location result/update relevant to ruler
  - manual-location update relevant to ruler
- State:
  - `isRulerEnabled`
  - `rulerMeasurement`
  - `rulerInfoWindow`
  - any ruler-specific deferred/fallback state if needed
- Reducer:
  - enable/disable ruler state
  - clear ruler state
  - commit new ruler measurement state
- Executor:
  - resolve ruler origin
  - handle fallback manual origin creation
  - invoke calculator/formatter when orchestration is needed
- Label:
  - only if a transient one-time output is required during migration; avoid unnecessary labels if ruler stays state-driven

## Migration Strategy
1. Identify all ruler-related conditions currently embedded in component methods
2. Route ruler-related intents through Store
3. Move pure ruler state transitions into reducer
4. Move fallback/deferred origin orchestration into executor
5. Keep current UI and render contracts stable where possible
6. Verify all `MAP-012` acceptance scenarios still hold

## Risks and Mitigations
- Risk: ruler origin priority changes unintentionally
  - Mitigation: preserve the existing resolution order explicitly in tests
- Risk: deferred fallback behavior regresses
  - Mitigation: keep first-snapshot behavior under dedicated tests
- Risk: GPS/manual updates stop re-binding the ruler start point correctly
  - Mitigation: migrate with scenario-level tests before removing compatibility logic
