# Plan — MAP-007

## Summary
Add a fixed center marker overlay in shared map UI, persist the last neutral camera snapshot in screen state for future product use, and prepare a click seam for a future geo-object creation menu without introducing business logic into the renderer.

## Affected Modules
- `feature/map/api`: extend screen contract and main state
- `feature/map/impl`: store last center snapshot in main state
- `feature/map/ui`: add center marker overlay
- `feature/map/render`: no business change expected
- `feature/map/render` android actual: no change expected unless minor wiring is required

## File-Level Plan
- Extend `MapScreenComponent.Model` with `lastCameraSnapshot`
- Add `onCenterMarkerClick()` to `MapScreenComponent`
- Update `DefaultMapScreenComponent.onCameraIdle(...)` to store the latest snapshot in main state
- Keep debug state separate from product state
- Add a shared `CenterMarker` composable
- Overlay `CenterMarker` in `MapScreenContent` with `Alignment.Center`
- Keep future menu logic out of this ticket

## Implementation Notes
- Keep `MapRenderer` render-only
- Keep `MapLibreCameraAdapter` camera observation-only
- Use the already available `onCameraIdle` callback as the stable center coordinate source
- Do not move MapLibre logic into shared code
- Avoid large touch surface or gesture conflicts for the marker
- Keep the marker visually small and clear

## Proposed Contracts
- `MapScreenComponent.Model(lastCameraSnapshot: MapCameraSnapshot?)`
- `MapScreenComponent.onCenterMarkerClick()`
- `CenterMarker(onClick: () -> Unit)`

## Risks
- Product state may remain incorrectly tied to debug state if not separated cleanly
- A too-large center marker may interfere with map gestures
- Future menu scope may accidentally expand this ticket
- If real-time coordinates are needed later, `onCameraIdle` will not be sufficient
