# Plan - MAP-007

## Summary
Implement the minimal map point interaction flow in the map feature: fixed center marker, stored neutral camera snapshot, bottom-sheet draft creation, neutral point rendering, and info window display for clicked points, while keeping renderer code platform-focused and business-agnostic.

## Affected Modules
- `feature/map/api`: screen contract, point model, and main screen state
- `feature/map/impl`: point creation, state orchestration, point selection, and presentation mapping
- `feature/map/ui`: center marker, create sheet, and shared info window overlay
- `feature/map/render`: neutral render model and renderer callback seam
- `feature/map/render` android actual: MapLibre click bridge and hit detection only

## File-Level Plan
- Keep `lastCameraSnapshot` in `MapScreenComponent.Model`
- Keep center marker interaction in shared screen/component flow
- Store created points in minimal in-memory map feature state with explicit point identity
- Map business points to neutral renderer points in a dedicated mapper
- Add a neutral renderer click callback carrying only renderer key and screen anchor
- Resolve clicked point back to business state in component layer only
- Map selected point to shared info-window UI state with local date formatting
- Render the info window in shared Compose above the map

## Implementation Notes
- Keep `MapRenderer` render-only
- Keep `MapLibreCameraAdapter` camera observation-only
- Keep Android-specific map click integration in `androidMain`
- Keep business state, UI state, and renderer contract separate
- Use minimal abstractions for point selection, point info-window mapping, and date formatting
- Keep touch-target improvements local to UI and Android hit detection only

## Proposed Contracts
- `MapScreenComponent.Model(lastCameraSnapshot, createPointDraft, selectedPointInfoWindow, ... )`
- `MapScreenComponent.onPointClick(pointKey, anchor)`
- `MapScreenComponent.onPointInfoWindowDismiss()`
- `MapPoint(id, latitude, longitude, title, createdAtEpochMillis)`
- `RenderPointClick(pointKey, anchor)`

## Risks
- Renderer callback could accidentally grow product semantics if not kept neutral
- UI overlay positioning could drift if stale anchors are not cleared on map movement
- Touch-target increases could interfere with map gestures if made too large
