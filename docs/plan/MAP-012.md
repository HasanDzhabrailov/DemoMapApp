# Plan - MAP-012

## Summary
Add a real ruler measurement mode that builds a temporary line from the user's current location to the current map center and shows a dedicated ruler information window. The start point must come from GPS if available, otherwise from manual location, otherwise from an automatically created fallback manual location at the current map center.

## Affected Modules
- `feature/map/api`
- `feature/map/impl`
- `feature/map/ui`
- `feature/map/render`
- `androidMain` map rendering only

## File-Level Plan
- Extend `MapScreenComponent` with explicit ruler measurement state
- Keep `isRulerEnabled`, but add dedicated shared ruler measurement data instead of treating the toggle as standalone UI state
- Update `DefaultMapScreenComponent` to manage ruler activation, fallback origin creation, and recalculation on camera changes
- Reuse `currentLocationMarker` as the ruler start-point source
- Add shared calculator(s) for distance and true azimuth
- Add shared formatter(s) for distance text and angle text
- Extend `MapRenderModel` with a dedicated temporary ruler render model separate from user-created lines
- Update `MapScreenContent` to show a dedicated `RulerInfoWindowOverlay`
- Update Android renderer to draw the temporary ruler line
- Keep ruler rendering out of feature click handling
- Update JVM renderer stub to accept the new API surface
- Add tests for ruler state machine, fallback manual location creation, and calculation behavior

## Architecture Notes
- `MapScreenComponent.Model` remains the owner of ruler state
- Compose remains UI-only
- The ruler information window is separate from shared feature info windows
- The ruler line is temporary render state, not persistent feature state
- The ruler start point is derived from `currentLocationMarker`
- If no current location marker exists, the component may create a manual placeholder location marker as a fallback
- Business calculations remain in shared code
- Renderer remains responsible only for drawing the temporary line
- MapLibre stays Android-specific
- The ticket should deliver reliable `distance` and `A`
- `Ам` and `α` should be represented only as future-extensible fields unless their formula is explicitly confirmed during implementation

## Proposed Shared Models
- `data class RulerMeasurement(val startLatitude: Double, val startLongitude: Double, val endLatitude: Double, val endLongitude: Double, val distanceMeters: Double, val trueAzimuthDegrees: Double)`
- `data class RulerInfoWindowState(val distanceText: String, val trueAzimuthText: String, val magneticAzimuthText: String? = null, val directionalAngleText: String? = null)`
- `data class RenderRulerMeasurement(val startLatitude: Double, val startLongitude: Double, val endLatitude: Double, val endLongitude: Double)`
- Optional: `enum class RulerOrigin { GPS, MANUAL }`

## Proposed State Additions
- `rulerMeasurement: RulerMeasurement? = null`
- `rulerInfoWindow: RulerInfoWindowState? = null`

## Proposed State Refinement
- Keep `isRulerEnabled`
- Continue using `currentLocationMarker` as the single source of current user location
- Do not add ruler data to `MapState`

## Proposed Intents
- Keep:
  - `onRulerToggle()`
  - `onCameraIdle(snapshot)`
- No new UI intents are required unless implementation reveals a missing explicit reset/restart action

## State Machine Rules
- Default state:
  - `isRulerEnabled = false`
  - `rulerMeasurement = null`
  - `rulerInfoWindow = null`

- `onRulerToggle()` when ruler is `OFF`:
  - switch `isRulerEnabled = true`
  - resolve ruler origin in this order:
    - existing GPS location marker
    - existing manual location marker
    - fallback manual placeholder from current camera snapshot
    - deferred fallback until first snapshot if no snapshot exists yet
  - if a start point and end point are available, build ruler measurement immediately

- `onRulerToggle()` when ruler is `ON`:
  - switch `isRulerEnabled = false`
  - clear `rulerMeasurement`
  - clear `rulerInfoWindow`

- `onCameraIdle(snapshot)`:
  - update `lastCameraSnapshot`
  - if ruler is active and no `currentLocationMarker` exists yet, create fallback manual placeholder at the current map center
  - if ruler is active and a start point exists, recalculate ruler measurement using:
    - start = current location marker
    - end = current map center from snapshot

- `onLocationResult(LocationResolved)`:
  - update `currentLocationMarker` using existing MAP-011 logic
  - if ruler is active, recalculate measurement from the new GPS point

- Manual my-location updates:
  - if ruler is active and GPS mode is not active, recalculate from the updated manual location marker

## Shared Calculation Plan
- Add a small shared calculator for:
  - geodesic distance in meters
  - true azimuth in degrees
- Add a small shared formatter for:
  - meters vs kilometers formatting
  - degree formatting in DMS for `A`
- Keep the formulas isolated from component state management

## Renderer Plan
- Extend `MapRenderModel` with `rulerMeasurement: RenderRulerMeasurement?`
- Draw the ruler line via a dedicated source/layer path
- Keep that layer out of feature click queries
- Do not reuse user-created line rendering for ruler state

## UI Layout Plan
- Keep existing menu, left controls, right zoom controls, and center marker behavior intact
- Add a dedicated `RulerInfoWindowOverlay`
- Anchor the info window near the ruler end point / current center presentation area using a simple stable overlay approach
- Do not reuse `PointInfoWindowOverlay` state or semantics

- `LSP`: GPS and manual markers are interchangeable as ruler origin through the same `currentLocationMarker` abstraction
- `ISP`: UI and renderer depend on narrow ruler-specific models
- `DIP`: shared ruler logic depends on shared map models, not Android or MapLibre APIs

## AGENTS.md Check

- Compose remains UI-only
- Android-specific code stays in `androidMain`
- MapLibre remains rendering-only

- Scope stays inside current map business area

## Risks and Mitigations
- Fallback manual origin may be created before a camera snapshot exists
  - Mitigation: defer fallback creation until first `onCameraIdle`
- Ruler line may accidentally behave like a user-created line
  - Mitigation: dedicated render model and dedicated renderer layer
- Location updates may unexpectedly change the ruler start point
  - Mitigation: make origin resolution rules explicit and test them
- `Ам` and `α` may be requested before formulas are defined
  - Mitigation: deliver reliable `distance + A` first and keep future fields optional
